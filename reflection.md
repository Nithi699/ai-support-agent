# Reflection: AI Support Agent

I built a customer support agent on Amazon Bedrock AgentCore that answers order questions, processes refunds, searches a knowledge base, remembers customer preferences, calculates loyalty discounts and reads web pages. The agent runs on AgentCore Runtime. Order and refund tools reach it through an AgentCore Gateway backed by an API Gateway and a Lambda function. Knowledge retrieval uses a Bedrock Knowledge Base, long-term memory uses AgentCore Memory, and the loyalty math runs in the Code Interpreter so the numbers are exact.

Most of the learning came from debugging the deployed agent. An unpinned `strands-agents-tools` upgrade removed its browser module, so the runtime crashed at import and the first call failed with an initialization timeout. Reading the CloudWatch logs led me to pin the version below 0.9.0. Later errors came from a renamed hook method, a gateway tool name that contained a hidden tab character, and a Lambda that expected underscored tool names while the gateway sent hyphenated ones. The knowledge base also returned the wrong content because its data source pointed at a CDK bootstrap bucket instead of my product catalog. Finally, Playwright's Node driver could not start in the runtime because a system library was missing, so I replaced the browser tool with a small custom tool that drives the AgentCore Browser over its WebSocket interface.

For production I would pin and lock every dependency and run an automated test after each deploy. I would validate tool schemas before publishing them, and secure the gateway with an authorizer instead of none. I would give each role least-privilege permissions and add CloudWatch alarms on error logs. Cost matters as well: the knowledge base's vector store bills while it exists, so I will delete the resources once the project is accepted. The main lesson is to read logs first, change one thing at a time, and retest after every fix.
